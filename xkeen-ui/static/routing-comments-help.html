Комментарии в routing-файлах Xray

Редактор XKeen UI понимает JSONC: обычный JSON с комментариями. Комментарии можно использовать для пояснений и временного отключения правил, не удаляя их.

Активный файл выбирается в панели. Обычно основной фрагмент называется 05_routing.json, но имя зависит от установленного профиля и ядра.

Как это работает сейчас
  • Поддерживаются комментарии: //, #, /* ... */.
  • Панель хранит редактируемый текст с комментариями в отдельном JSONC sidecar-файле.
  • Для Xray рядом с остальными фрагментами записывается очищенный валидный .json. Сам Xray комментарии не читает.
  • Перед сохранением панель проверяет синтаксис JSONC, структуру routing и запускает Xray preflight.
Главное: обычное сохранение не должно удалять комментарии из текста редактора. Если отдельная операция не может сохранить их безопасно, панель предупреждает до перезаписи.

1. Поддерживаемые комментарии

1.1. Однострочный комментарий //

// Комментарий целой строки
{
  "routing": {
    "rules": [
    // Комментарий перед правилом
    { "type": "field", "outboundTag": "proxy" } // Комментарий в конце строки
    ]
  }
}

1.2. Однострочный комментарий #

# Комментарий целой строки
{
  "routing": {
    "domainStrategy": "AsIs", # Комментарий в конце строки
    "rules": [
      # комментарий внутри списка
      { "type": "field", "outboundTag": "direct" }
    ]
  }
}

1.3. Многострочный комментарий /* ... */

{
  /*
    Большой блок комментария:
    - можно описать, что делает конфиг
    - кто его правил
    - когда вносились изменения
  */
  "routing": {
    "rules": [
      {
        "type": "field",
        "ip": ["geoip:private"],
        "outboundTag": "direct"
      }
    ]
  }
}

Последовательности //, # и /* внутри строки в двойных кавычках остаются частью строки и не считаются комментариями.

2. Сохранение и статусы комментариев

Строка состояния под редактором показывает, откуда загружен текст и удалось ли сохранить комментарии при операции:

  • JSONC activeSidecar найден и его версия с комментариями открыта в редакторе.
  • sidecar найденJSONC-копия существует, но основной JSON новее и отличается. Панель показывает актуальный JSON, чтобы не затереть внешнее изменение.
  • offSidecar ещё не создан. При сохранении он будет создан вместе с очищенным JSON для Xray.
  • JSONC preserveОперация над правилами применилась с сохранением комментариев.
  • нужен fallbackАвтоматически сохранить расположение комментариев не удалось; перед полной перезаписью потребуется подтверждение.

JSONC sidecar хранится в служебном каталоге панели, отдельно от каталога конфигурации Xray. Это сделано специально: Xray не должен пытаться загрузить файл с комментариями как конфигурационный фрагмент.

3. Типичные ошибки

3.1. Висячая запятая перед закрывающей скобкой

После удаления комментариев JSON не должен содержать лишних запятых.

Неправильно:

{
  "routing": {
    "rules": [
      { "type": "field", "outboundTag": "proxy" }, // лишняя запятая
    ]
  }
}

Правильно:

{
  "routing": {
    "rules": [
      { "type": "field", "outboundTag": "proxy" } // без запятой
    ]
  }
}

3.2. Незакрытый многострочный комментарий

Неправильно:

{
  /* Начали писать
     большой комментарий и забыли закрыть
  "routing": { "rules": [] }
}

Правильно:

{
  /* Всё ОК */
  "routing": { "rules": [] }
}

3.3. Повреждённая структура JSON

Комментарии не отменяют требования JSON: ключи и строки должны быть в двойных кавычках, а все скобки — закрыты.

{
  "routing": {
    "rules": []
  }
}

4. Как устроен routing-фрагмент

В актуальных фрагментах массив правил находится в routing.rules. Каждое правило — отдельный объект. Часто используются:

  • domain — домены и списки GeoSite;
  • ip — IP/CIDR и списки GeoIP;
  • network, port, protocol, inboundTag — дополнительные условия;
  • outboundTag или balancerTag — назначение правила. Указанный тег должен существовать в текущей конфигурации.

Минимальный пример с двумя правилами:

{
  "routing": {
    "domainStrategy": "IPIfNonMatch",
    "rules": [
      // Локальные сети — напрямую
      {
      "type": "field",
        "ip": ["geoip:private"],
        "outboundTag": "direct"
      },
      // Пример доменного правила
      {
      "type": "field",
        "domain": ["domain:example.org"],
        "outboundTag": "proxy"
      }
    ]
  }
}
Порядок важен: Xray проверяет правила сверху вниз. Размещайте более точные исключения раньше общих правил.

5. Безопасная работа в панели

  • Для обычных изменений используйте RAW-редактор или карточки правил — они синхронизированы с текущим текстом.
  • Перед сохранением исправьте все сообщения JSONC/schema. Клик по ошибке переводит редактор к проблемному месту.
  • Если Xray preflight не проходит, файл не записывается. Проверьте неизвестные outbound/balancer tags, GeoIP/GeoSite и синтаксис значений.
  • Команда удаления комментариев делает это явно. Сортировка и некоторые массовые сценарии могут попросить подтверждение, если сохранить комментарии на прежних местах невозможно.
  • Если конфигурацию изменили вне панели, статус sidecar найден защищает более новый основной JSON от тихой перезаписи старой JSONC-копией.
