# Экран «Логи Xray»

Переделан 22 октября 2026 года по макетам, согласованным с владельцем. Этот документ описывает устройство экрана и то, что нельзя сломать при правках.

## Что видит пользователь

- **Шапка в одну строку:** название и состояние потока, переключатель `access` / `error` со счётчиками, выбор уровня Xray (только для `error`), группа **Пуск ⇄ Пауза / Стоп**, поиск (клавиша `/`), меню «⋯» и полный экран.
  - **Пуск:** если Xray уже пишет логи, запускается только онлайн-поток. Если запись выключена, сначала включается запись логов, и ядро перезапускается.
  - **Пауза:** стоит на месте Пуска, пока идёт поток. Замораживает вывод, строки продолжают копиться.
  - **Продолжить:** та же кнопка на паузе, рядом число накопленных строк. Только размораживает вывод, запись логов не трогает.
  - **Стоп:** выключает запись логов Xray (`loglevel=none`, перезапуск ядра).
- **Меню «⋯»:** раздел «Вид» (следить за концом, домены рядом с IP, сводка, неразобранные строки, автообновление, размер окна, интервал опроса) и раздел «Данные» (копировать видимое, скачать, загрузить старые строки, обновить снимок, имена устройств, очистить экран). Очистка файлов стоит отдельно, красным, за разделителем.
- **Сводка (только access.log):** в свёрнутом виде одна строка с долями proxy/direct/block/dns, в развёрнутом — четыре плитки: куда уходит трафик, узлы, устройства, домены. Плитки узлов, устройств и доменов никогда не считают DNS-запросы; полоса трафика показывает долю dns, только когда чип dns включён. Домен для IP берётся из подсказок доменов (кэш DNS), без подсказки остаётся IP; 127.0.0.1 и ::1 не считаются. Клик по строке плитки добавляет условие фильтра. Развёрнута сводка или нет, запоминается в браузере.
- **Чипы:** для access.log маршрут (proxy/direct/block/dns) и узлы, для error.log уровни. Чип dns по умолчанию отжат: DNS-запросы клиентов к слушателю (`xk-dns-listener → dns-out`) и собственные запросы ядра (`from DNS …`, через любой узел или direct) скрыты, счётчик на чипе виден. Включённый dns запоминается в браузере, «Сбросить» снова его отжимает. У запроса ядра полоска dns, а в столбце «Маршрут» — настоящий outbound (поле `outKind` разбора). Активные условия «только это устройство / домен / узел / модуль / соединение» снимаются крестиком.
- **Таблица.** Колонки access.log: время, устройство, назначение, маршрут, порт. Колонки error.log: время, уровень, модуль, сообщение. Стрелка справа или двойной клик раскрывают подробности: исходная строка, быстрые фильтры, «Копировать строку», «Имя устройства…».
- **Выбор строк:** клик, Shift+клик, Ctrl+клик, Ctrl+A, Ctrl+C, Esc. Полоса снизу предлагает «Копировать строки лога» (исходные строки) и «Копировать таблицей» (колонки через табуляцию).
- **Неразобранные строки** по умолчанию скрыты: в подвале виден только счётчик, показать их можно в меню.

## Журнал операций Xkeen

Карточка под логами (и на экранах Xkeen, Routing, Mihomo, «Команды») — один шаблон `templates/panel/journal_card.html`, рисует её `static/js/features/restart_log.js`. Стили — блок `.xk-jr-*` в конце `panel-operator.css`.

- **Шапка как у логов Xray:** «Все / Ошибки» с числами, поиск, меню «⋯» (обновить, копировать журнал, красным — очистить), полный экран. Сводка — одна строка: последний перезапуск, ядро, число ошибок.
- **Строка = операция:** полоска итога, время `чч:мм:сс`, источник (клик — фильтр по нему), сообщение с главной деталью (файл, «было: Xray», уровень логов), «вывод · N», длительность, стрелка. Смена дня — строка-разделитель.
- **Вывод команды свёрнут под своей операцией.** Панель пишет вывод xkeen и ядра в `restart.log` прямо перед строкой результата той же операции (`routes/service.py`, `_flush_runtime_log`), поэтому строки без `source=` относятся к следующей записи с `source=`. Вывод без строки результата после него (команда идёт или ничего не сообщает) — отдельная группа «Вывод», она открыта, пока её не свернут.
- **Раскрытая строка:** вывод (время Mihomo из UTC переводится в местное), подробности ключ — значение, «Открыть разбор ошибки» для preflight, «Копировать запись», «Только «источник»». Раскрытые строки переживают опрос раз в 15 с; разметка перерисовывается, только если изменилась.
- **Телефон:** общее правило «кнопка не ниже 40 px» перебивается через id пяти экранов, как в логах Xray, иначе плашки источников и переключатель раздуваются.

## Устройство

| Файл | Роль |
|---|---|
| `static/js/features/xray_log_parser.js` | Разбор строк access.log и error.log в записи. Чистые функции, тесты в `tests/test_xray_log_parser_js.py` гоняют их в `node`. |
| `static/js/features/xray_log_view.js` | Вывод: записи, фильтры, счётчики, виртуальная таблица, чипы, сводка, выбор строк. |
| `static/js/features/xray_logs.js` | Контроллер: WebSocket/HTTP, курсор, пауза, настройки, имена устройств, подсказки доменов, меню, контекст строки. |
| `static/js/ui/country_flags.js` | Страна узла по имени (флаг-эмодзи, код в начале, город или страна) и SVG-флаги. Общий для Mihomo и Xray. |
| `routes/xray_logs.py` → `GET /api/xray-logs/outbound-names` | Имена узлов подписок по тегам. Тег теряет эмодзи-флаг, имя узла его сохраняет. |

Формат access.log и варианты, которые разбор понимает: `->` (правило), `>>` (маршрут по умолчанию), `==>` (балансировщик), голый тег, источник с `tcp:`/`udp:`, IPv6 в скобках, `rejected` с причиной и без назначения, `email:`, источник `DNS` без порта (так пишет встроенный DNS-клиент Xray). Корпус с роутера 22.10.2026: 129 из 129 строк access.log и 877 из 877 строк error.log.

## Почему так и что нельзя ломать

1. **Строки рисуются в теневом DOM** у `#xray-log-output` со своей маленькой таблицей стилей (`VIEW_CSS`). Сверка новых строк с большим `panel-operator.css` стоила больше всего остального вместе. Цвета панели (`--op-*`) наследуются внутрь как обычно. Стили строк меняются в `VIEW_CSS`, а не в `panel-operator.css`.
2. **Строка разбирается один раз,** когда приходит. Счётчики чипов и сводки ведутся по мере поступления, а чипы и сводка перерисовываются не чаще раза в секунду.
3. **В DOM только видимые строки** плюс запас (около 40). Строка таблицы привязана к своей записи: при новых строках заполняются только новые, а сдвиг при обрезке буфера — это один `transform` на контейнере.
4. **Положение прокрутки вычисляется** из числа строк и высоты окна. Чтение `scrollHeight` после изменений DOM вызывало принудительную раскладку на каждое обновление.
5. **Высота строки фиксирована:** 32 px, заголовок таблицы 30 px. На этом держится виртуализация. Длинное сообщение обрезается и целиком показывается в подробностях.
6. **Шапка и подвал обновляются бережно.** Атрибуты, текст и подсказки пишутся только при изменении, Пуск и Пауза обе лежат в разметке и только прячутся по очереди, у Пуска меняются лишь подпись («Пуск» / «Продолжить») и счётчик. Если пересобирать кнопку на каждой новой строке, клик теряется: элемент под курсором заменяется между нажатием и отпусканием мыши. Так было на 45.1 23.10.2026, теперь это ловит тест паузы.

## Замер

Стенд: Chromium, процессор замедлен в 4 раза, в буфере 5000 строк, приходит по 50 новых строк в секунду, 20 секунд, опрос по HTTP раз в секунду.

| | access.log, до | access.log, после | error.log, до | error.log, после |
|---|---|---|---|---|
| Кадров за 20 с | 8 | 1127 | 2 | 1116 |
| Пересчёт стилей | 14,7 с | 0,5 с | 16,2 с | 0,5 с |
| Длинные задачи (сумма) | 25,4 с | 0 | 21,7 с | 0,36 с |
| Самая длинная задача | 8,3 с | — | 21,5 с | 93 мс |
| Узлов DOM в выводе | 5600 | ~400 | 18000 | ~300 |

Запись трассы Playwright (`trace: 'retain-on-failure'`) снимает DOM после каждого изменения и на таком потоке занимает почти всё время. Замеры производительности снимать с `--trace off`.
