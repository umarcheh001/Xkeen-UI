# Обновление подписок Mihomo / Prizrak

Подходящие управляемые подписки переводятся из статических `proxies:` в файловые
`proxy-providers`. Панель продолжает скачивать источники, передавать HWID,
преобразовывать Xray JSON и обслуживать расписание. Ядро получает готовые файлы
`proxy_providers/xkeen/xk-managed-*.yaml` и перечитывает только изменившиеся
providers через `PUT /providers/proxies/{name}`.

Первичный перенос требует одного `PUT /configs?force=false` с серверным путём к
активному YAML. Для оставшихся статических подписок используется тот же reload.
`force=false` не запрашивает принудительное пересоздание портовых слушателей.
При недоступном API статический путь сохраняет прежний fallback через рестарт.
Невалидный YAML не применяется: файлы и состояние возвращаются к предыдущему
снимку. Ошибка provider API возвращает прежний файл и содержимое provider в
runtime без fallback-рестарта.

## Пакеты, HTTP и ошибки

Все кандидаты пакета сначала готовятся в памяти. Выполняются одна запись конфига,
одна запись состояния и один бэкап на пакет, затем обновляются изменившиеся
providers. При отсутствии изменений нет бэкапа и применения. Перед записью
повторно проверяется, что пользователь не изменил YAML во время скачивания.

ETag/Last-Modified сохраняются вместе с URL и отпечатком заголовков запроса.
Валидатор одного HWID/User-Agent не используется для другого. Ответ 304 позволяет
переиспользовать сохранённые узлы. `restart=false` сохраняет режим «только сохранить»;
отложенное применение фиксируется отдельно и не теряется при следующем 304.

После ошибки повторы назначаются через 5, 15 и 60 минут, с ограничением обычным
интервалом подписки. Успешная проверка сбрасывает счётчик ошибок. Последнее успешное
обновление хранится отдельно от последней попытки.

## Совместимость и бэкапы

Миграция сохраняет порядок подписок в группах. Правила/listeners/dialer-proxy,
ссылающиеся на отдельный узел, группы с подмножеством узлов и конструкции,
которые нельзя безопасно заменить на `use:`, остаются статическими.
Чужие providers и ручные узлы не перенастраиваются. Ручные изменения других
частей конфига допускают миграцию только при точном совпадении всех управляемых
узлов с сохранённым снимком. Сам YAML целиком не сериализуется заново.

Бэкапы YAML включают inline-снимки managed providers, поэтому восстановление
возвращает прежние узлы даже после перезаписи рабочих файлов providers.
Последующее обновление снова материализует inline-снимок в файл. Совпадение
времени бэкапов до секунды больше не перезаписывает предыдущий снимок.

Ответ содержит `changed`, `not_modified`, `hot_applied`, `restarted` и при
применении `apply_method`: `mihomo-provider`, `mihomo-api` или `restart`.

`/opt/etc/xkeen-ui-providers-backup-20261125`.
