# Перекомпоновка вкладки Tools в DevTools

Дата: 17 сентября 2026. Статус: согласовано (вариант D), ждёт плана работ.

## Задача

Вкладка Tools (`templates/devtools.html:93`) устроена как двухколоночная сетка
`minmax(300px, 420px) / 1fr`: слева «поднос» с **девятью** карточками подряд,
справа единственная карточка ENV (whitelist) высотой почти во весь экран
(`.dt-env-scroll` — `calc(100vh - 260px)` в основной теме,
`calc(100vh - 210px)` в теме оператора).

Следствия, которые видно глазом:

- под ENV справа остаётся пустота на полтора-два экрана;
- карточкам слева ширины не хватает физически. В «Шапка / Брендинг» восемь полей
  переименования вкладок сжаты до нечитаемых огрызков; в «Терминал (xterm.js)»
  лежит `#dt-term-fields` — **27 цветовых полей** (11 базовых + 16 ANSI,
  `static/js/features/devtools/terminal_theme.js:55`), которые сеткой
  `.dt-theme-grid` в две колонки вытягивают карточку почти на 900 px;
  в «Layout‑твиках» — редактор порядка вкладок с перетаскиванием.

Цель: отдать вспомогательным блокам ширину, разбить их на именованные зоны и
сохранить верхний ряд как «первый экран» — то, зачем в DevTools заходят.

## Решение

Экран делится на **три именованные зоны**. Внутри каждой — сетка в две колонки;
карточка, которой нужна вся ширина, растягивается на обе.

| Зона | Карточки (id сохраняются) | Раскладка |
|---|---|---|
| Сервис, обновление и настройки | `dt-service-card`, `dt-update-card` \| `dt-env-card` | существующий `.dt-tools-layout`, левая колонка вровень с ENV по высоте |
| Система | `dt-happ-decryptor-card` \| `dt-logging-card`; `dt-terminal-theme-card` | пара, под ней широкая полоса (свёрнутая по умолчанию) |
| Вид интерфейса | `dt-branding-card`; `dt-ui-prefs-card` \| `dt-ui-prefs-io-card`; `dt-layout-card` | широкая, пара, широкая |

Ритм страницы получается такой: верхний ряд на весь первый экран, затем
чередование пар и широких полос — пара, широкая, широкая, пара, широкая.

### Поправка к макету D

В макете, по которому принято решение, зона «Система» была нарисована как ряд из
трёх равных карточек, а «Вид интерфейса» — как широкий Брендинг плюс ряд из трёх.
Макет упрощал три карточки: у «Терминала» не были показаны 27 цветовых полей, у
«Layout‑твиков» — редактор порядка вкладок, у «Экспорт / Импорт» — два поля
`rows="6"`, из-за которых карточка на самом деле втрое выше нарисованной.
С реальным содержимым ряд из трёх даёт ровно ту болезнь, из-за которой макет и
переделывали: соседи высокой карточки растягиваются пустотой.

Поэтому в зонах вместо «ряда из трёх» — **пара плюс широкая полоса**. Оценка высот
по составу разметки (при ширине зоны ≈ 1560 px):

| Карточка | В паре (≈780 px) | Во всю ширину |
|---|---|---|
| Декриптор Happ | ≈ 240 | — |
| Логирование | ≈ 230 | — |
| Интерфейс | ≈ 250 | — |
| Экспорт / Импорт | ≈ 600 сейчас, ≈ 260 после перестройки в две колонки | — |
| Шапка / Брендинг | ≈ 520 | ≈ 330 |
| Layout‑твики | ≈ 400 | ≈ 330 |
| Терминал (xterm.js) | ≈ 900 | ≈ 480 раскрытый, ≈ 56 свёрнутый |

Внутри пар высоты сходятся (240 против 230 и 250 против 260), широкая полоса
Брендинга и Layout‑твиков даёт 330, свёрнутый терминал — тонкую полосу заголовка.
Рваных колонок и висящего воздуха не остаётся.

Распределение по пулам из макета сохранено: «Терминал» остаётся в «Системе», просто
занимает всю ширину, а не треть.

## Каркас

Новые примитивы (базовые правила — в `static/styles.css`, рядом с `.dt-tools-layout`):

```css
.dt-zone-block { margin-top: 24px; }

.dt-zone-head { /* подпись зоны + волосяная линия */ }

.dt-zone {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 14px;
  align-items: stretch;
}

.dt-zone > .dt-card-wide { grid-column: 1 / -1; }
```

Перестановка карточки между парой и широкой полосой — это перенос узла в разметке
плюс класс `dt-card-wide`. Ничего, кроме этого, менять не требуется.

Карточки в паре выровнены по высоте (`stretch` — поведение сетки по умолчанию):
пара читается одной полосой, а не двумя обрывками. Чтобы выравнивание не
оборачивалось пустотой, карточка, у которой есть растяжимый элемент, отдаёт
слабину ему — как хвост `update.log` в верхнем ряду и поля ввода в «Экспорт /
Импорт» (см. ниже). Пары подобраны так, что естественные высоты соседей близки.

Разметка зоны:

```html
<section class="dt-zone-block">
  <div class="dt-zone-head" aria-hidden="true">Система</div>
  <div class="dt-zone" role="group" aria-label="Система"> … карточки … </div>
</section>
```

Заголовки карточек остаются `<h2>`, подпись зоны намеренно не заголовок: она
`aria-hidden`, а группировку для скринридера даёт `role="group"` + `aria-label` на
сетке. Так уровни заголовков не переезжают и не тянут за собой правки CSS и тестов.

### Равная высота верхнего ряда

`.dt-tools-layout` сохраняет две колонки и свои значения `grid-template-columns`
в обеих темах. Меняется выравнивание и поведение левой колонки:

- `.dt-tools-layout { align-items: stretch; }` — «поднос» тянется до низа ENV;
- `.dt-tools-left` — флекс-колонка (уже так и есть);
- `#dt-update-card[open] { flex: 1 1 auto; min-height: 0; }` — слабину забирает
  карточка обновления;
- внутри неё слабину поглощает хвост лога: `#dt-update-log-box` получает
  `flex: 1 1 auto; min-height: 0`, а `#dt-update-log` — `overflow: auto`. Больше
  видимых строк `update.log` — побочная польза, а не просто растяжка воздухом.

Если карточка обновления свёрнута, поднос остаётся короче ENV — это нормально и
специально не лечится.

### Терминал свёрнут по умолчанию

Цветовая схема терминала — самая редкая настройка на вкладке и самая дорогая по
площади: 27 полей даже в четыре колонки занимают около 480 px. Поэтому карточка
`dt-terminal-theme-card` открывается **свёрнутой**: у неё снимается атрибут `open`
в разметке. В свёрнутом виде это полоса заголовка на всю ширину — около 56 px.

Выбор пользователя запоминается существующим механизмом, дописывать ничего не
нужно: `wireCollapsibleState({ selector: 'details.dt-collapsible[id]',
storagePrefix: 'xk.devtools.collapse.' })` (`static/js/features/devtools.js:20`,
реализация — `static/js/ui/shared_primitives.js:187`) на каждый `toggle` пишет
`xk.devtools.collapse.dt-terminal-theme-card.open`, а при следующем заходе
восстанавливает состояние. Разметка задаёт только значение по умолчанию —
для того, у кого сохранённого состояния ещё нет. Состояние сворачивания уже
входит в экспорт UI‑настроек, так что переносится вместе с ними.

Инициализация модуля темы терминала остаётся как есть (`idleDelay: 1800` плюс
раскрытие карточки, `static/js/features/devtools.js:210`) — поведение не меняем.

### Внутренности карточек, получивших ширину

Правки локальные, каркаса не касаются:

- **Шапка / Брендинг**: «Заголовок панели», «Лого», «Favicon» — в три колонки;
  `.dt-rename-list` — в четыре.
- **Терминал**: `.dt-theme-grid` на широкой полосе — четыре колонки (сейчас две,
  `static/styles.css:12844`); 27 полей укладываются в семь строк вместо четырнадцати.
  Это раскладка для раскрытого состояния; по умолчанию карточка свёрнута.
- **Layout‑твики**: переключатели и селекты — в две колонки, редактор порядка
  вкладок — рядом с ними, а не под ними.
- **Экспорт / Импорт UI‑настроек**: сейчас карточка вытянута двумя полями
  `rows="6"` подряд (`#dt-ui-prefs-export-text`, `#dt-ui-prefs-import-text`) и в паре
  с «Интерфейсом» смотрится обрубком другой высоты. Блоки «Export JSON» и
  «Import JSON» встают в две колонки, `rows` перестаёт определять высоту:
  поля получают `flex: 1 1 auto; min-height: 96px` и растягиваются по высоте
  карточки, «Reset all» уходит в подвал одной строкой. Карточка становится
  ростом с «Интерфейс», а слабину пары забирают поля ввода — видимых строк JSON
  становится больше, а не появляется пустота.

### Адаптив

`.dt-zone` переходит в одну колонку на тех же порогах, что уже используют темы:
`max-width: 1024px` в базовом слое, `max-width: 1180px` в слое оператора.
`grid-column: 1 / -1` в одноколоночном режиме безвреден. Внутренние сетки
карточек (3–4 колонки) сходятся к одной по своим существующим media-правилам.

### Пустая зона

Единственный механизм, который может опустошить пул целиком, — ENV-вайтлист
секций (`static/js/ui/sections.js`, переменная `XKEEN_UI_DEVTOOLS_SECTIONS_WHITELIST`):
он ставит элементу инлайновый `display: none` и `data-xk-force-hidden="1"`.
Чтобы от скрытого пула не оставалась висящая подпись:

```css
.dt-zone-block:not(:has(> .dt-zone > *:not([data-xk-force-hidden]))) { display: none; }
```

Твик «Скрыть неиспользуемые вкладки/карточки» на эти карточки не влияет — он про
вкладки за feature-флагами (`static/js/features/file_manager.js:206`).

## Чего нельзя нарушить

- класс `.dt-tools-layout` остаётся: его наличие проверяют
  `tests/test_devtools_operator_theme.py:69` и `:96`;
- в слое оператора должна сохраниться строка
  `grid-template-columns: minmax(400px, 440px) minmax(0, 1fr);` — её проверяет
  тот же тест дословно;
- id всех девяти карточек сохраняются: по ним ходят e2e, отложенная инициализация
  и якоря вида `#dt-update-card`;
- атрибуты `data-xk-section` остаются на карточках: это контракт ENV-вайтлиста;
- у каждой карточки сохраняется её акцент и глиф (`--dt-side-accent`,
  `--dt-card-glyph`) — сейчас они заданы по id, а сам `::before` привязан к
  `.dt-tools-left > *` и требует расширения селектора.

## Тесты

Новое:

- `tests/test_devtools_tools_zones.py` — сторож против рассинхрона разметки:
  все девять id присутствуют по одному разу; семь карточек лежат внутри `.dt-zone`;
  в `.dt-tools-left` остались только сервис и обновление; у каждой `.dt-zone` есть
  `aria-label`; зон ровно три; у трёх широких карточек есть `dt-card-wide`;
  у `dt-terminal-theme-card` **нет** атрибута `open`, а у остальных шести
  раскрываемых карточек он сохранён.
- e2e-спек на раскладку (`e2e/devtools_tools_zones.spec.mjs`): при 1600 px видны три
  подписи зон, карточки в ожидаемых зонах, горизонтального скролла нет, низ подноса
  совпадает с низом карточки ENV (допуск 2 px — это и есть проверка требования
  «по высоте вровень»); «Интерфейс» и «Экспорт / Импорт» одной высоты (тот же
  допуск); при 900 px всё сходится в одну колонку.
- e2e-спек на память сворачивания (`e2e/devtools_terminal_collapsed.spec.mjs`):
  при первом заходе карточка терминала свёрнута и её поля не видны; после клика по
  заголовку и перезагрузки страницы она остаётся раскрытой, а в хранилище лежит
  `xk.devtools.collapse.dt-terminal-theme-card.open = "1"`; после повторного клика
  и перезагрузки — снова свёрнута.

Правим существующее:

- `tests/test_devtools_operator_theme.py` — в список обязательных якорей слоя
  оператора добавляем `.dt-zone`.

Прогон: `pytest` из Bash (из PowerShell падает `test_version_check`), перед e2e
обязателен `npm run frontend:build`. Визуальных эталонов у DevTools нет — ни один
devtools-спек не использует `toHaveScreenshot`, так что переснимать нечего.

Проверить руками обе темы (основную и оператора) и светлую/тёмную, а также узкий
экран: ширина, на которой зоны сходятся в одну колонку, не должна оставлять
горизонтальный скролл.

## Чего в этой работе нет

- **Сводок текущих значений в заголовках карточек** — решено делать второй
  итерацией. Каркас от них не зависит: сводка добавляется в заголовок карточки,
  не в зону.
- Логика самих карточек, их запросы и обработчики не меняются.
- Вкладка Logs не трогается.
- Разделение карточек на более мелкие, вынос редактора темы терминала в отдельное
  окно и прочие идеи по содержимому — вне этой задачи.

## Приёмка

1. При 1600 px справа под ENV нет пустого экрана, ниже идут три подписанные зоны.
2. Поднос слева кончается на одной линии с карточкой ENV; хвост `update.log`
   скроллится внутри.
3. В Брендинге все восемь полей переименования читаемы целиком.
4. Терминал при первом заходе свёрнут в полосу заголовка; раскрытый укладывается
   в семь строк полей вместо четырнадцати; раскрытое (как и снова свёрнутое)
   состояние переживает перезагрузку страницы.
5. «Интерфейс» и «Экспорт / Импорт» в паре одной высоты, поля JSON занимают
   свободное место внутри карточки, а не оставляют пустоту под ней.
6. `pytest` и e2e зелёные; тема оператора и светлая тема не разъехались.
7. `XKEEN_UI_DEVTOOLS_SECTIONS_WHITELIST` с урезанным списком не оставляет
   подписей от опустевших зон.
