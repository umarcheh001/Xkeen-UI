# Окно диагностики: предупреждение о сценарии остановки служб Entware (opkg initrc)

Дата: 27.10.2026. Размер: небольшая правка.

## Зачем

Если в конфигурации прошивки нет `opkg initrc /opt/etc/init.d/rc.unslung`, при перезагрузке роутера
прошивка не вызывает `rc.unslung stop`. Службы Entware не останавливаются штатно, панель получает
SIGTERM уже после перевода `/opt` в режим только для чтения, и история диагностики теряется (до часа,
см. `FLASH_SAVE_EVERY_S`). Так было на 45.1 (NC-1812, 5.1.8): каждая загрузка начиналась с
«removing stale pid file». После ручной команды `opkg initrc …` перезагрузка сохранила историю.
Пользователь об этом сам не узнает — панель должна заметить и предложить исправить одной кнопкой.

## Цели

- Окно «Диагностика роутера» показывает предупреждение, когда `initrc` не задан.
- Кнопка «Исправить» → подтверждение на месте → панель выполняет `opkg initrc /opt/etc/init.d/rc.unslung`
  и `system configuration save` → зелёная полоса «Готово».
- Кнопка «Скрыть»: больше не напоминать (запоминается на роутере).

## Не цели

- Установщик настройку не меняет (вариант В отклонён на этом этапе).
- Центр уведомлений не трогаем.
- Не чиним «чужой» `initrc` (если задан другой путь — это выбор пользователя, предупреждения нет).

## Подходы (выбор владельца)

- **А — полоса в окне диагностики** (выбрано): там видны дыры в графиках, там их и чинить; инфраструктура готова.
- Б — запись в центре уведомлений: центр построен вокруг каталога выпусков, переделка ради одного случая.
- В — установщик сам прописывает: молча меняет конфигурацию роутера.

Вид — макеты https://claude.ai/artifact/MbBHXkpq5LLcTYTESKuuvv: выбран вариант **А** (отдельная полоса под
строкой состояния; строка состояния остаётся как есть), шаг подтверждения — **да**, кнопка «Скрыть» — **нужна**.
Тексты — как на макетах (владелец замечаний не дал).

## Как устроено

**Проверка (сервер).** Новый модуль `services/entware_initrc.py`:
- `initrc_status()` → `{"state": "ok" | "missing" | "unknown", "path": str | None}`.
  Источник — `run_ndmc("show running-config")` (только через `utils/firmware.py`), очистка ESC-последовательностей
  как в `dns_over_vless._dns_override_status`. Есть строка `opkg initrc <путь>` → `ok`; нет её, но есть
  `opkg disk …` → `missing`; ndmc недоступен, ошибка или нет `opkg disk` → `unknown` (полоса не показывается).
- Результат кэшируется в процессе (настройка меняется редко); кэш сбрасывается после «Исправить».
- `apply_initrc()` — две отдельные команды `ndmc -c` (одна команда на вызов, как в `_set_dns_override`),
  проверка вывода на `% error`/`error:`; затем повторная проверка `initrc_status()` — успех только если стало `ok`.

**Скрытие.** `ui_settings` → `diagnostics.initrc_hint_dismissed: true` (рядом с `diagnostics.tariffs`).

**API** (blueprint `routes/system_resources.py`):
- `GET /api/system/router/initrc` → `{ok, state, path, dismissed}`.
- `POST /api/system/router/initrc/apply` → `{ok, state}` или ошибка с текстом прошивки (`code`, `details`).
- `POST /api/system/router/initrc/dismiss` → `{ok}`.

**Окно (фронт).** `resource_monitor/view.js` (+ стили в `view_css.js`): слот под строкой состояния. Запрос
`GET …/initrc` при открытии окна (один раз, не на каждом тике). Состояния полосы: предупреждение
(«Исправить», «Скрыть») → подтверждение («Прописать», «Отмена») → выполняется (кнопки заблокированы) →
«Готово» (зелёная, до закрытия окна) или ошибка (текст + «Повторить»). На телефоне кнопки под текстом.

## Проверки

- pytest: разбор running-config (есть/нет/чужой путь/нет opkg/ndmc недоступен), `apply` с ошибкой прошивки
  и с успехом, скрытие через ui_settings, ответы API.
- e2e (`router_resource_dashboard`): полоса видна при `missing`, не видна при `ok`/`unknown`/`dismissed`;
  путь «Исправить → Прописать → Готово»; ошибка и «Повторить»; «Скрыть»; без горизонтальной прокрутки на 390 px.
- Роутер: на 10.1 (`initrc` задан) полосы нет; на 45.1 временно `no opkg initrc` → полоса → «Исправить» →
  перезагрузка сохраняет историю. Менять конфигурацию роутера — только с согласия владельца.
