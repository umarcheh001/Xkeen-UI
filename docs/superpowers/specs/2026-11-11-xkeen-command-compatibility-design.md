# Доступность команд XKeen

## Цель и границы

Показывать команды с учётом установленного XKeen, добавить восемь согласованных команд и уточнить описания `-d` и `-dm`. Сохранить поддержку старых выпусков. `-pbr` и `-killswitch` с аргументами рассматриваются отдельно после этого этапа; голые флаги не добавлять. Не выполнять XKeen, его справку или другие shell-скрипты для обнаружения возможностей.

## Выбор способа

Запуск `xkeen -h` не подходит: проверенные версии до вывода справки могут перемещать каталог XKeen и удалять файл установщика; текущая версия также содержит такой код. Таблица по номеру версии не определяет особенности форков и промежуточных сборок. Предлагается читать установленный файл команды как данные, без выполнения, и распознавать только проверенные форматы диспетчера флагов. Сверять результат с образцами официальных выпусков 1.1.3.9, 2.0, 2.1 и 2.2 Beta; не пытаться исполнять shell для разбора.

Распознавание должно быть консервативным: ограничить размер чтения, проверить наличие полной структуры диспетчера и опорных флагов, учитывать изменения формата и симлинки, а при любой неоднозначности вернуть «неизвестно», а не объявлять команды отсутствующими. Присутствие обработчика подтверждает только наличие флага, но не работоспособность окружения. Для форков и нестандартных установок нужна проверка на образцах до окончательного выбора парсера; если надёжно определить отсутствие невозможно, сообщать «неизвестно».

## Поведение панели

- В распознанной установке отображать только подтверждённые флаги каталога, скрывая не поддерживаемые; не оставлять пустые группы и пересчитать счётчики.
- При неизвестной доступности явно указать, что проверить не удалось; существующие команды не пропадают неожиданно. Для новых команд не утверждать, что они поддерживаются. Состояние после обновления XKeen должно пересчитываться, а не жить до перезапуска панели.
- Подтверждённые `-health`, `-cfd`, `-di`, `-xtest`, `-mtest`, `-dscp`, `-startvb`, `-sb` добавить в соответствующие группы. Указать, что `-health` может затрагивать пакеты, `-dscp` открывает управление, а `-di` без числа показывает значение. Подтверждение макета касается расположения; подписи должны отражать фактическое поведение.
- Существующие `-uy` и восемь старых команд также учитывать при определении доступности. Уточнить описание `-d`; текст `-dm` согласовать после проверки старых выпусков, не утверждая универсальность поведения одной версии.
- Панель работает с PTY и с облегчённым терминалом; проверять оба пути. Существующий API с отдельным разрешённым флагом не должен начинать исполнять произвольные аргументы. Явно проверить, как пользователю объясняется отказ и что происходит, если состояние XKeen изменилось после отображения страницы.

## Проверки

Тесты на образцах разных выпусков и модифицированных/неполных файлов, ошибки чтения, нестандартные ссылки, отсутствующий XKeen и отсутствие побочных действий; проверка обновления результата при замене файлов. Тесты каталога и отображения, а также запуск в доступных режимах терминала. Сборку запускать перед e2e. На роутер не устанавливать без отдельной просьбы.
