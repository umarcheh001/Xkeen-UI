# Сохранение истории при остановке панели

Владелец разрешил исправление после обнаружения пропуска при установке:
старый процесс принудительно завершён через 3 секунды, tmp-копия отставала.
Точный источник задержки внутри процесса не установлен; подтверждена
недостаточность окна остановки и отсутствие свежей резервной копии в RAM.

Выбран подход: на SIGTERM сначала сохранять историю в tmpfs, затем на флешку;
служба ждёт выхода до 15 секунд (выбор исполнителя), после этого применяет
SIGKILL и пишет причину в журнал. Журналирование остановки выполняется в фоне
с отвязанными stdin/stdout/stderr после отправки сигнала: медленный bootlog
не блокирует checkpoint и эскалацию. Обычный ранний выход не задерживается.
Установщик уже ставит этот init-скрипт перед restart; путь не дублируем.

Альтернативы: только увеличить ожидание — при медленной флешке всё ещё нет
свежей RAM-копии; ждать бесконечно — зависшая панель блокирует обновление.
Новый HTTP endpoint/протокол checkpoint для этой правки не вводится.
Выход после успешного обработчика означает завершение сохранений; ошибки
сохранения логируются. При зависании/ошибке обоих носителей гарантий нет.

Не увеличивать частоту периодической записи; реальные пропуски сбора и первый
замер после запуска не заполнять. Уже потерянные данные не восстанавливать.
Код локально в pre-release; новый коммит, push и установка требуют команды.
