# Отладка маршрутизации Xray

Согласовано владельцем в диалоге 14.11.2026, команда на реализацию «делай».

Отдельный переключатель «Отладка маршрутизации» — третий в «Вид», после доменов
и сводки. Default off; намерение хранится на роутере и общее для браузеров.
Ниже Xray26.3.27 и при неизвестной версии переключатель недоступен с причиной.
Переключение при остановленном журнале сохраняет намерение, без старта ядра.
Пуск применяет hooks с loglevel одним restart; Стоп снимает hooks, сохраняет
намерение и полученный снимок. Пауза замораживает представление, не ядро.
Переключение во время журнала требует restart, об этом сказано в подсказке.

Правила показываются только при выбранном режиме; warning достаточен.
Условия, порядок и теги маршрутизации не меняются. Свои hooks снимаются при
выключении; чужие не перезаписываются. Существующие механизмы отображения,
паузы, TSV и подтверждения доменов обычного режима сохраняются. Старое
определение ruleTag из error.log удаляется, дублирующий fallback не нужен.
Сводка срабатываний не входит в первую версию.

## Подход

Автоматическое включение при debug отклонено в пользу отдельного режима без
лишних диагностических строк. Источник — штатный per-rule webhook, проверенный
на Xray26.11.9 при warning; минимум upstream26.3.27.

Приёмник встроен в Flask blueprint Xray. Он принимает только loopback POST с
секретом в заголовке, ограничивает тело16КиБ и проверяет поля. Для единственного
машинного endpoint глобальный guard использует эту проверку вместо session/CSRF;
все пользовательские endpoint сохраняют прежнюю защиту. Секрет генерируется
локально и хранится с режимом0600, наружу в status не возвращается.
URL указывает на127.0.0.1 и настроенный серверный порт, не на Host запроса.
Opaque rule key связывает событие с конкретным правилом; имя из payload не принимается.

Конфигурация и состояние изменяются под общим lock с откатом при ошибке проверки,
записи или restart. До записи используется штатный check_staged; JSONC-комментарии
сохраняются штатным renderer/sidecar. Собственные URL/headers распознаются по
секрету/префиксу; чужие webhook остаются нетронутыми. Пропущенные правила отражены
в status. При смене конфигурации старая корреляция не должна назначать чужие теги.

Приёмник хранит максимум2048 событий и TTL30с, отдаёт их пачкой через общий опрос
метаданных. Нет записи на диск каждого события и запроса на каждую access-строку.
Потери/неоднозначность дают прочерк. Временной штамп webhook секундный: проверяем
source/target/network/inbound/outbound и окно2с; одинаковые кандидаты не считаются
доказательством. Настройка меняет поколение данных. Остановленный снимок остаётся
в браузере, после выключения переключателя колонка скрывается.

## Проверки и замеры

TDD: версия/намерение/права/пределы/сопоставление/чужие hooks/откат; API auth;
e2e warning, третья позиция, off, старое/неизвестное ядро, пауза/Стоп/поколение.
До/после: браузер CPU×1/×4,0/50/500 строк/с, время ingest/render, ограниченность
DOM/очереди/кеша. Native Xray: direct/block, warning/debug, недоступный/медленный
приёмник, доставленные события и CPU/RSS/задержка соединений. На роутер без отдельной
команды ничего не устанавливается. Новые зависимости не добавляются.
