# Интернет после перезагрузки — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Первые отрицательные проверки интернета при загрузке дают серый промежуток без ложных событий, с пределом 120 секунд uptime.

**Architecture:** Одно состояние ожидания в ResourceHistoryCollector; проверка готовности до обновления self._internet, online и событий. График, карточка и журнал используют общий результат. Сохранённая история не переписывается.

**Tech Stack:** Python, pytest, существующие FakeRouter и ResourceHistoryCollector.

**Spec:** docs/superpowers/specs/2026-10-28-router-internet-startup-design.md

## Global Constraints

- Ожидание до первого internet=true, не дольше 120 секунд от загрузки роутера, по uptime.
- После первого internet=true настоящий обрыв фиксируется сразу.
- Не создавать новое окно ожидания при позднем запуске панели.
- Не менять вёрстку, стили, сохранённые события, формат истории и настройки роутера.
- Python LF; без установки, пуша, тегов и релизов без отдельной просьбы.

## Review Focus

- Часы перескакивают при NTP: граница ожидания зависит только от uptime.
- Сборщик перезапустился: первый отрицательный ответ при uptime>=120 остаётся аварией.
- Нет uptime или нет RCI: отсутствие сведений не должно бессрочно скрывать настоящий сбой.
- Первое подключение раньше 120 секунд: последующее отключение не подавляется.
- Восстановлена история: запуск не создаёт новой пары lost/restored и не сбрасывает подпись; прежний журнал сохраняется.
