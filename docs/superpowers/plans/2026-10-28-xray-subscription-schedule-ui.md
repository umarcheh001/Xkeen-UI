# План: расписание и ошибки подписок Xray

Основа: `docs/superpowers/specs/2026-10-28-xray-subscription-schedule-ui.md`.
Существующий cron остаётся источником истины; произвольное выражение нельзя
терять при открытии формы. Интервалы и API подписок сохраняют совместимость.

1. Покрыть тестами первый штатный сбой, повторные ошибки, успешное обновление,
   ручные и старые записи. Добавить независимые даты успеха и первого сбоя без
   выдумывания прошлого; не нарушить имеющийся короткий повтор при ошибке.
2. Реализовать обратимое преобразование простых выражений cron и формы (день,
   дни недели, число месяца); все неоднозначные выражения оставлять ручными.
   Проверить месяцы без выбранного числа, пустые дни, формат времени и отсутствие
   потери cron при открытии/отмене/сохранении.
3. Обновить форму по утверждённому макету, затем список по варианту А:
   пояснение расписания, понятная ошибка и даты без отображения секретов.
   Инвалиды и ожидание серверной проверки не должны допускать сохранение.
4. Проверить сохранность интервального режима и рекомендаций провайдера,
   исключение cron из выравнивания, локальное время роутера, keyboard и темы.
   Сборка перед E2E, целевые и полные тесты, описи; проверить CRLF фронта.
5. Сверить реализацию с макетами и документом, записать результаты и ограничения.

## Выявленная особенность перед реализацией

`last_update_ts` записывается и при ошибке, а ошибка любой попытки переносит
`next_update_ts` на короткий повтор. Поэтому одного сравнения текущего времени
с `next_update_ts` недостаточно: ручная неудачная попытка до штатного срока
может породить повторы раньше него. Нужны тесты, различающие штатный срок,
ручное обновление и повтор после него, прежде чем менять состояние подписки.
Имеющийся срок и поведение повторов необходимо сохранить совместимыми.
