# Первичная установка Xray и Mihomo

**Цель:** установить отсутствующее ядро из выбранного источника, сохранив работу текущего ядра и устранив неверное сообщение о модуле.

**Спецификация:** `docs/superpowers/specs/2026-11-09-first-core-install-design.md`.

**Ограничения:** одинаковое поведение для Xray и Mihomo; скачивание только проверенного релиза с SHA-256; первичная установка не переключает ядро и не перезапускает XKeen; установка на роутер только по отдельной просьбе. Изменения покрываются сначала падающими тестами. Коммиты и пуш без отдельного поручения не выполнять.

## 1. Доступность управления и состояние модуля

Файлы: `xkeen-ui/routes/__init__.py`, `xkeen-ui/routes/pages.py`, `xkeen-ui/services/module_registry.py`, `tests/test_modular_panel_stage4_5_composition.py`, тесты маршрутов и активации модулей.

- [ ] Зафиксировать тестами реальные состояния при запуске без Xray и без Mihomo: модуль установлен и выбран, но недоступен только из-за отсутствия соответствующего ядра; выключенный и неустановленный модуль; другие причины недоступности.
- [ ] Обеспечить доступность только управления источником и первичной установкой для выбранного установленного модуля, ожидающего отсутствующее ядро; остальные маршруты недоступного модуля не включать. Не расширять права для выключенного или неустановленного модуля.
- [ ] Передать в окно различимые состояния и проверить оба варианта после настоящего построения страницы, а не одной подменой клиентского ответа.

## 2. Установщик отсутствующего ядра

Файлы: `xkeen-ui/services/core_installer.py`, `xkeen-ui/routes/core_profiles.py`, `tests/test_core_installer.py`, `tests/test_core_profiles_routes.py`.

- [ ] Параметризованными тестами для Xray и Mihomo зафиксировать успешную установку отсутствующего файла из подтверждённого релиза без вызова перезапуска и без изменения активного ядра.
- [ ] Проверить отказ при смене состояния между подготовкой, подтверждением и записью, при наличии файла до записи, при переключении ядра, неверной контрольной сумме и недоступном релизе; проверить очистку и сохранность текущего ядра.
- [ ] Ввести отдельную явно проверяемую ветку первичной установки, сохраняя строгую проверку активного ядра для обновления. Повторно проверять состояние и защищать создание файла от перезаписи при гонке.
- [ ] Проверить корректную запись состояния источника и безопасное обновление состояния панели после установки; при необходимости использовать штатный механизм перезапуска панели, не службы XKeen.

## 3. Окно управления

Файлы: `xkeen-ui/templates/panel/core_source.html`, `xkeen-ui/templates/panel/modals/shared.html`, `xkeen-ui/static/js/features/core_source.js`, `xkeen-ui/static/js/features/service_status.js`, соответствующие стили и `e2e/core_windows.spec.mjs`, `e2e/core_source_selection.spec.mjs`.

- [ ] Добавить проверки обоих реальных сценариев отсутствующего ядра, выключенного модуля, смены источника и кнопки с версией; загрузка и ошибка источника не позволяют начать установку.
- [ ] Реализовать согласованные макеты: одинаковые по ширине кнопки, существующая иконка источника, выделенная установка с версией, примечание о продолжающейся работе текущего ядра. Состояние без работающего ядра описывать корректно.
- [ ] Настроить подтверждение, ход операции, ошибки и обновление интерфейса после установки; не показывать обещание отката предыдущего бинарника, когда его нет.

## 4. Проверка

- [ ] Запустить соответствующие pytest-файлы, полный `npm run test:py` и проверить ошибки; до e2e выполнить `npm run frontend:build`.
- [ ] Запустить затронутые e2e-спеки и проверить отсутствие регрессий для существующего обновления и выбора источника, а также `git diff --check` и окончания строк.
- [ ] Записать актуальный результат в `.superpowers/handoff.md` и при необходимости в память; отдельно указать то, что не проверено на роутере.
