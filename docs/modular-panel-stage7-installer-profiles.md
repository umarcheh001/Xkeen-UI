# Этап 7. Профили установщика

Статус: закрыт 2 октября 2026 года. Следующий этап: менеджер официальных модулей (Этап 8).

## Состав профилей

| Профиль | Модули | Редактор |
| --- | --- | --- |
| `full` / `legacy-full` | Все штатные модули | `full` |
| `xray-minimal` | `core`, `engine.xray`, `tool.editor` | `light` |
| `mihomo-minimal` | `core`, `engine.mihomo`, `tool.editor` | `light` |
| `custom` | Явный список с `core` и зависимостями выбранных модулей | `light` по умолчанию |

Установщик использует один официальный архив. Профиль выбирается интерактивно на новой установке либо задаётся через `XKEEN_UI_INSTALL_PROFILE`; для `custom` требуется `XKEEN_UI_INSTALL_MODULES` с ID через запятую. При повторной установке и self-update профиль и Custom-набор читаются из `modules.json`, если переменные не заданы явно. Наличие файла `module-installed.json` отражает установленный состав уже на первом запуске.

## Применение и восстановление

`scripts/module_profile_install.py` выбирает module-owned Python, шаблоны, исходные JS и build-assets. Импорты Python выбранных модулей включаются в замыкание зависимостей; для Vite manifest сохраняются необходимые static imports. Общий bootstrap пока статически импортирует часть Mihomo chunks, поэтому отдельные общие chunks остаются даже в Xray Minimal. Их самостоятельное разделение относится к дальнейшей оптимизации frontend.

Перед изменениями проверяется свободное место. Предыдущее состояние заменяемых файлов копируется в `xkeen-ui.profile-transaction-*` рядом с панелью. Файлы отключённых модулей, устаревшие `.gz`, manifest и generated assets помещаются в `quarantine` внутри этого каталога. После применения сохраняются `modules.json`, `install-profile.json`, `module-installed.json` и `install-managed.json`. Если запуск сервиса не прошёл, `install.sh` вызывает rollback, восстанавливая старые файлы и профиль. После успешного запуска резервная копия и quarantine остаются для ручной проверки и восстановления.

Пользовательские конфигурации, `secret.key`, `xray-jsonc`, Mihomo profiles/backup и runtime state исключены из managed-набора. Старые файлы без сведений об ownership из установки до Этапа 7 не удаляются произвольно; штатные generated assets и `.gz` всё равно очищаются. Отдельные архивы модулей и точечные обновления остаются задачей Этапа 8.

## API

`POST /api/modules/profile` атомарно сохраняет профиль и возвращает состояние registry с `changed`, `restart_required` и `diff`: профиль до/после, модули после перезапуска, новые и отключаемые модули, недоступные требования. Для `custom` передаётся `module_ids`; `editor_variant` необязателен. API изменяет конфигурацию, но не загружает файлы модулей: для смены физического состава используйте установщик. Защита от отключения активного ядра и DNS действует и для смены профиля.

Локальная проверка покрывает оба минимальных состава импортом приложения, переход Full -> Minimal, повторное обновление, сохранение конфигураций, очистку `.gz`, нехватку места, rollback и API. Проверка на Keenetic/Entware с реальным init-скриптом остаётся релизным smoke-тестом.
